# Production hardening — Phase 2: security and privacy assessment

Date: 2026-11-10 · App version 0.12.0 (commit `2ae05ff`) · Assessment only: no code changed.
Builds on [phase-1-discovery.md](phase-1-discovery.md). Target: ASVS 5.0 L1, L2 for auth,
session, data protection and logging; MASVS-L1 for Android.

## 1. Method

- **Live, read-only probes** of the production Supabase project using only the public
  publishable key (no accounts created, no data written): public auth settings, anonymous
  table reads, anonymous RPC calls, Edge Functions without a token, CORS pre-flight.
- **Live headers** of https://ascend-vert-mu.vercel.app.
- **Code review** against OWASP Top 10 (2021), API Security Top 10 (2023) and MASVS: auth and
  session (`auth.ts`, `sync/client.ts`), access control (all migrations, both functions), input
  validation (action schemas, sync apply, backup import, zip import, photo upload), output
  encoding (React rendering, links), logging (`errorLog.ts`), PWA caching (`vite.config.ts`),
  Android components and intents (manifest, all 15 Java classes' intent handling), AI flow.
- **Existing automated evidence**: `src/core/sync/sql.test.ts` runs the real migrations in
  Postgres (PGlite) and checks cross-user isolation and anonymous denial.

## 2. Controls verified as working (evidence)

| Control                                 | Evidence                                                                                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Anonymous users cannot read synced data | `GET /rest/v1/sync_records` with the public key → **401** `permission denied for table sync_records`                                                                                                                      |
| No direct writes; RPCs need sign-in     | anon `push_records`, `reset_my_cloud_data`, `ask_take` → **42501 permission denied**                                                                                                                                      |
| Cross-user isolation (IDOR)             | RLS `user_id = auth.uid()` on reads; writes only via definer functions using `auth.uid()`, never a client-supplied id. Test: `sql.test.ts:72` "a user only ever sees their own rows; anonymous users can't read or write" |
| Edge Functions require a valid user     | `POST /functions/v1/ask` and `/delete-account` without a token → **401**; user id taken from the token (`auth.getUser`), never the body                                                                                   |
| Secrets server-side only                | OpenRouter key and service-role key live only in Edge Function env; no secret in client code or 176 commits (pattern scan)                                                                                                |
| OAuth / magic link                      | PKCE flow (`flowType: 'pkce'`), code exchanged in-app; the custom-scheme redirect can't be replayed without the verifier                                                                                                  |
| Injection                               | No SQL built from strings (PostgREST + parameterised plpgsql); every action Zod-validated; sync apply validates shape, table allow-list and schema version                                                                |
| XSS                                     | No `innerHTML`/`eval`/`document.write`; React escapes all text; external links `rel="noreferrer"`; Ask sources limited to `https://`                                                                                      |
| Deep links                              | `app.ascend.rishi://open/…` reduced to `[a-z0-9/-]` and routed in-app only (`deepLink.ts`)                                                                                                                                |
| Android intents                         | All PendingIntents `FLAG_IMMUTABLE`; service, boot receiver and FileProvider not exported                                                                                                                                 |
| PWA cache                               | Workbox precaches static files only; no runtime caching of API or auth responses                                                                                                                                          |
| Backup import                           | Zod-validated envelope, per-table key fields, schema-version ceiling                                                                                                                                                      |
| Production dependencies                 | `npm audit --omit=dev` → 0 vulnerabilities                                                                                                                                                                                |
| TLS                                     | HSTS `max-age=63072000; includeSubDomains; preload` (Vercel); Supabase HTTPS only                                                                                                                                         |

## 4. Privacy assessment

- **Data minimisation to third parties: good.** Only Ask sends data out (OpenRouter), and only
  an allow-listed set of goal/skill numbers (test-enforced); never health, journal, mood,
  photos, screen time. A local outbound log records each request.
- **Device storage:** IndexedDB (app-private) — fine; weak points are V-04 and V-05.
- **Server storage:** see V-07. Account deletion cascades all rows (verified in code).
- **Free AI models:** OpenRouter free endpoints may log prompts (README says so) — accepted
  by you; the allow-list keeps that to non-sensitive numbers.
